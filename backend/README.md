# Backend

Java 25 / Spring Boot 4.0.0. Run `mvn verify` then `mvn spring-boot:run`, or build the included Dockerfile. Port 8080. Optional server-only `GITHUB_TOKEN` improves GitHub request allowance; never expose it in the frontend. No local storage or repository checkout is used.

## API

- `GET /api/health` → `{"status":"ok"}`
- `POST /api/analyze`, JSON `{"url":"https://github.com/owner/repo","ref":"optional branch, tag or commit SHA"}`.
- Success: `repository:{owner,name,url,ref}`, `nodes:[{id,label,path,buildTool,dependencies}]`, `edges:[{source,target}]`, `cycles:[[id]]`, `stats:{modules,edges,externalDependencies,cycles,filesScanned,totalFiles,languages}`, `warnings:[string]`.
- `repository.ref` is resolved immutable commit SHA. Use it in share links to reproduce a snapshot. Node IDs are `maven:path` / `gradle:path`, root path `.`. Edges point **from dependent to dependency**.
- `cycles` are strongly connected cycle groups, including self-loops, not every simple cycle. External dependencies count unique unresolved direct coordinates; unresolved Gradle project references are warned and excluded. `filesScanned` counts downloaded build files, including files failing parser validation; `totalFiles` counts blob entries in the available tree. `languages` maps selected filename extensions to file counts, not GitHub language bytes or full language detection.
- Errors `{error,message}`: 400 invalid input/public-only, 404 not found, 413 body too large, 429 busy/GitHub allowance, 502 upstream failure/oversize, 503 interrupted, 504 timeout. Partial results explicitly include warnings. GitHub 403 is deliberately surfaced as upstream access/rate-limit rather than claiming repository absence.

## Security and limits

Only exact HTTPS github.com owner/repository URLs accepted (no ports, credentials, query or fragment). Requests are constructed against fixed `https://api.github.com` only; caller URLs are never fetched. Redirects are disabled. Tree/blob IDs are validated, references encoded, private metadata refused even when a token can read it. Repository scripts, wrappers, plugins and dependencies are never run. XML DTDs and external entities disabled. Nothing is extracted to disk.

At most 2 analyses in flight. 32-entry in-memory result cache expires after 5 minutes; deployments should additionally use authenticated access or reverse-proxy per-client rate limiting if internet-exposed. Request body max 8 KiB. Upstream connect timeout 5 seconds, each full response max 12 seconds, analysis deadline 45 seconds, 8 MiB tree response, 100 build/settings files (settings first, then lexical order), each max 512 KiB decoded, total max 8 MiB source. Dependencies are deduplicated and capped at 500 per module / 10000 total, with partial warnings; unresolved project warnings capped at 20 plus count. XML depth capped at 128. Parsing adds a bounded amount of time after network deadline. Oversized trees fail safely; truncated trees and skipped files are clearly marked partial. No hidden unlimited retries. GitHub rate exhaustion after some build files yields partial results; exhaustion before analysis yields 429.

## Static-analysis limitations

This MVP discovers pom.xml/build.gradle/build.gradle.kts and settings.gradle/settings.gradle.kts, not necessarily only active reactor modules. Maven reads direct dependencies, inherits only parent groupId, and does not resolve properties, profiles, dependencyManagement, inherited dependencies or remote parents. Gradle recognizes literal project dependencies and common quoted external dependency coordinates; literal settings include declarations and projectDir=file('path') or File(rootDir/settingsDir, 'path') mappings are supported. Declared modules without build files are included. Nested settings scope aliases to the nearest build root. Settings contribute up to 400 declared modules and never access the filesystem. No DSL execution, computed settings/projectDir evaluation, version catalogs or convention plugin resolution. Triple-quoted/slashy strings and nested Kotlin comments are not fully tokenized. Conditional declarations are approximated. Dynamic builds can be incomplete. Mixed build files at the same directory produce separate modules. Dependency versions are intentionally not part of graph identity; Maven matching is groupId:artifactId only and explicitly warned. Ambiguous duplicate Maven coordinates do not create internal edges. Languages only cover common source extensions. No source-level class/call graph.

`CoreChecks` provides a dependency-free executable parser/URL regression suite; `StaticAnalyzerTest` invokes it under JUnit. Maven/Java25 and live GitHub integration verification must be reported separately from static inspection.

Local verification: `sh test-core.sh` passed on the available Java 21 compiler module. This is not a full Spring Boot build, filter JUnit execution, Java 25 validation, or live GitHub integration test.

Additional verified core cases: Kotlin/Groovy settings includes, buildless modules, projectDir aliases, outgoing dependencies from mapped modules, nested build scoping, unsafe paths, and dynamic-settings warnings.

`ApiIntegrationTest` is an offline MVC/JSON contract smoke test. It runs the request-size filter, controller, real GitHub response decoding, Maven parser, graph construction, result serialization and cache using a strict in-memory GitHub HTTP fixture. It verifies directed module edges, immutable refs, file/language counts, cached requests, and invalid/malformed/oversized request rejection without network access. It does not prove live GitHub connectivity, the JDK HTTP response-body limiter, or a deployed servlet container.

The Compose CI job also captures desktop/mobile PNGs and rendered HTML of the explicitly labelled synthetic demo, alongside application logs, in the `demo-screenshots-and-compose-logs` artifact (14-day retention). Screenshot capture and DOM checks are not a visual review; inspect the PNGs before claiming layout verification. These captures do not represent live repository analysis.

For an explicit live connectivity check, manually dispatch CI with `live_github` enabled. It analyzes `mkakim95/spring5webapp`, requires a resolved commit and nonempty modules, and saves the response in the same artifact. This opt-in step fails visibly on GitHub outages/rate limits; normal CI remains offline for analysis, and no successful live run is implied by its configuration.

## Private self-managed GitLab (local-only)

Configure backend environment variables `GITLAB_BASE_URL=https://gitlab.company.example` (optionally a fixed installation subpath / explicit HTTPS port) and `GITLAB_TOKEN` with a minimally scoped `read_api` token authorized for the intended projects. Keep secrets out of browser fields, URLs, logs, Git and frontend build arguments. No paid service is required. The application makes only GET requests; it never executes repository code. A narrower project access token is preferable where available. Token and reports are not persisted by the application; the token exists only in process configuration/memory.

The UI submits the usual `{url,ref}`. Nested namespaces are supported. Only the exact operator-selected GitLab authority and installation path are permitted; arbitrary UI hosts, HTTP, credentials, query strings, fragments, encoded path tricks and repository subpage URLs are rejected. Private-address access is intentional only for this configured host. Redirects are never followed, including same-host redirects. API metadata URLs and pagination links are never used as fetch targets. GitLab numeric project ID, immutable commit SHA and blob IDs pin the snapshot; keyset continuation tokens are extracted only after validating the next-link authority and exact tree path, then re-encoded into locally constructed requests.

`repository.provider` is `github` or `gitlab`; `repository.shareable` is true for public GitHub and false for **all GitLab** reports, regardless of project visibility. GitLab analyses bypass the server result cache entirely and reauthorize/refetch each time. API responses include `Cache-Control: no-store`, `Pragma: no-cache`, and `Referrer-Policy: no-referrer`. Do not manually publish private result screenshots or copied graph data.

The supported deployment is loopback-only, single-user. The backend rejects non-loopback HTTP Host and browser Origin values to mitigate DNS rebinding/cross-site requests. This is **not user authentication** and does not isolate multiple users on the same machine. Do not publish the backend port or expose the service on LAN/internet. An authenticated multi-user deployment, authorization isolation and reverse-proxy rate limits require a separate design; forwarding `Host: localhost` is not authentication.

TLS certificate and hostname verification remain enabled. For a corporate CA, mount an operator-managed Java truststore read-only and configure standard JVM `javax.net.ssl.trustStore` settings without disabling TLS verification. No insecure HTTP or trust-all fallback exists. An empty/missing token returns a sanitized configuration error; tokens are never returned in API errors.

GitLab tree enumeration uses keyset pagination with at most 100 pages × 100 entries, 1 MiB/page and 8 MiB total tree bytes. Existing 45-second fetch budget, 100 build/settings files, 512 KiB/file, 8 MiB source, two concurrent analyses and parser limits remain. Limits/rate exhaustion produce explicit partial warnings where a useful partial snapshot exists. Unsupported/unsafe pagination fails closed. GitLab 401/403 becomes sanitized 403, 429 becomes 429, redirects/upstream failures become 502. GitLab Free/self-managed REST endpoints are sufficient; server/version-specific behavior still needs a test against the operator's actual instance.

Verification: dependency-free GitLab input allowlist tests run through `sh test-core.sh`. `GitLabIntegrationTest` supplies offline HTTP fixtures for nested namespace lookup, numeric project resolution, commit pinning, keyset pagination, graph output, token header scoping, no-cache repeat analysis, redirect/unsafe-link refusal and localhost Host/Origin rejection. Full Maven execution and real corporate GitLab connectivity must be reported separately.
